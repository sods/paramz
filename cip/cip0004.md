# CIP-0004: Unify and revive user-facing documentation

## Status

- [x] Proposed - Initial idea documented
- [ ] Accepted - Approved, ready to start work
- [ ] In Progress - Actively being implemented
- [ ] Implemented - Work complete, awaiting verification
- [ ] Closed - Verified and complete

## Summary

Make published paramz documentation trustworthy again: Sphinx under `doc/` as the single primary API reference (ReadTheDocs), fix README build/link instructions, compress CIP-0002/0003 outcomes into that surface, and retire or clearly demote the checked-in epydoc tree under `docs/` / GitHub Pages.

**Requirements:** REQ-0007.

## Motivation

After the 0.10.x work, README and many docstrings match behaviour, but hosted docs do not:

- ReadTheDocs Sphinx site last meaningfully updated years ago; `doc/source` is a thin stub that regenerates via `sphinx-apidoc`.
- GitHub Pages serves legacy epydoc HTML from `docs/` (`http://opendsi.cc/paramz/`).
- README still tells people to run `sphinx-apidoc` against `../GPy/` and points at RTD without saying which site is authoritative.
- VibeSafe flags CIP-0002 and CIP-0003 as needing compression (`compressed: false`); pickle and reload guidance must not live only in governance files and CHANGELOG.

CIP-0001 adopted VibeSafe on the assumption that Sphinx/RTD remains the user-facing API docs. This CIP delivers that assumption.

## Detailed Description

### Design decision: one primary home

**Choose Sphinx → ReadTheDocs as the primary published API documentation.**

Rationale:

- Already linked from README; `pyproject.toml` has an optional `docs` extra with Sphinx.
- Autodoc from live source tracks the 0.10.x API better than a frozen epydoc dump.
- Epydoc is obsolete; keeping Pages as a second “current” site guarantees drift.

**Legacy `docs/` epydoc:** stop presenting it as current. Preferred path: change GitHub Pages to build Sphinx output (or disable Pages and rely on RTD only). Minimum acceptable path: leave `docs/` in the tree but remove README/Pages “current docs” claims and add a short historical notice. Prefer not to keep dual live sites.

### What to publish (content)

Beyond regenerated API modules, add a short narrative page (Sphinx RST) covering:

1. **Parameter buffer model** — one copy in memory; NumPy 2-safe linking (CIP / REQ-0002 context).
2. **Serialization** — prefer `np.save` of `param_array` + reconstruct script; pickle of linked children is cycle-safe but not a durable cross-version format (CIP-0002).
3. **Reload** — use `m[:] = values` (notifies); bare `param_array[:]` is silent (CIP-0003 / #51).

These compress CIP-0002 and CIP-0003 into formal docs; then set `compressed: true` on those CIPs.

### Build and maintainer workflow

- Fix README compile instructions: `sphinx-apidoc -o source/ ../paramz` (or conf.py’s existing RTD hook), `make html`.
- Ensure `doc/source/requirements.txt` / RTD config is enough to build on current Python.
- Optionally add a lightweight CI job or documented `whats-next` compression target via `.vibesafe/documentation.yml` pointing at Sphinx — nice-to-have, not blocking.

### Out of scope

- Full tutorial rewrite or GPy user guide.
- Implementing auto-notify on `param_array.__setitem__` (explicitly deferred in CIP-0003).
- Changing runtime APIs.

## Implementation Plan

1. **Accept this CIP** and close CIP-0001 (governance adoption complete; user docs owned here).
2. **Fix README** documentation section (build path, primary link, demote or drop misleading badges/paths).
3. **Repair Sphinx project** under `doc/` so `make html` succeeds locally against current `paramz`.
4. **Add narrative RST** (serialization & reload / buffer model) and wire into `index.rst` toctree.
5. **Republish** ReadTheDocs from `main`; confirm a fresh build.
6. **Resolve Pages / `docs/`** (redirect, disable, or historical label — pick one in the implementing PR).
7. **Mark CIP-0002 and CIP-0003** `compressed: true`; close this CIP when acceptance criteria for REQ-0007 hold.

## Backward Compatibility

No runtime API change. URL changes for anyone bookmarked on epydoc Pages should use a redirect or an explicit “moved to RTD” stub if Pages stays up.

## Testing Strategy

- Local: `cd doc && make html` (or equivalent) exits 0.
- RTD: successful build on `main` after merge.
- Manual: README links resolve to the primary site; serialization page states `m[:]` vs `param_array[:]` and pickle guidance.
- VibeSafe: `./whats-next --compression-check` no longer lists CIP-0002/0003 once `compressed: true`.
