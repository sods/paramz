# CIP-0003: Notifying parameter reload API

## Status

- [x] Proposed
- [x] Accepted
- [x] In Progress
- [x] Implemented
- [x] Closed

## Summary

Resolve #51: make the recommended save/load path notify observers. Shipped as documentation + regression test; deferred auto-notify wrapper on `param_array.__setitem__`.

## Motivation

`param_array[:] = loaded` updates the shared buffer but does not call `_trigger_params_changed()`, so views and predictions stay stale while the flat array looks correct. Downstream GPy docs repeated this pattern.

## Detailed Description

Two layers:

1. **Docs (shipped):** Clarify that in-place `param_array` writes do not notify; recommend `m[:] = …` or an explicit trigger after deliberate buffer writes. README load example already used `m[:]`; prose and `param_array` docstring now match.
2. **Optional API (deferred):** Notifying `__setitem__` on the array returned by `param_array` is riskier for batching (`update_model(False)`, `randomize`, gradcheck). Left out of this change; reopen if docs prove insufficient.

## Implementation Plan

1. Patch `param_array` docstring and README load example.
2. Add regression test: silent `param_array[:]` vs notifying `m[:]`.
3. Defer auto-notify wrapper.
4. Close #51 when this lands; coordinate GPy #1217 docs separately if needed.

## Backward Compatibility

Docs-only + test. No runtime behaviour change for existing `m[:]` users.
