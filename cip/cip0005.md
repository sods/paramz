# CIP-0005: Restricted unpickler for paramz.load

## Status

- [x] Proposed - Initial idea documented
- [x] Accepted - Approved, ready to start work
- [ ] In Progress - Actively being implemented
- [ ] Implemented - Work complete, awaiting verification
- [ ] Closed - Verified and complete

## Summary

Close [issue #60](https://github.com/sods/paramz/issues/60) (CWE-502): stop using stock `pickle.load` in the public loader. Keep pickle as the on-disk format for the GPy ecosystem, but route `_unpickle` through a restricted `Unpickler` whose `find_class` allow-lists expected modules. Provide an explicit opt-in for unrestricted loads.

**Requirements:** REQ-0008.

## Motivation

`paramz.load` → `_unpickle` in `paramz/__init__.py` calls `pickle.load` with no trust boundary. A file whose payload uses `__reduce__` to invoke `exec` (or similar) runs under the user's privileges when loaded. `GPy.load` delegates here; model pickles are routinely shared and published, so the impact is not limited to local scratch files.

CIP-0002 fixed linked-child pickle round-trips. It did not address deserialization trust. This CIP is the security follow-up.

## Detailed Description

### Design choice

**Keep pickle; restrict the public loader.** Moving to JSON/HDF5 (or another inert format) would be the durable long-term fix, but it breaks GPy and existing archives. That migration is out of scope here but is being considered for cross package interaction between GPc and GPy (see CIP0016 in "Shared JSON/YAML model interchange with GPy and GPmat").

### Restricted Unpickler

Introduce a small helper (e.g. `paramz.core.safe_pickle` or next to `_unpickle`) that subclasses `pickle.Unpickler` and overrides `find_class(module, name)`:

**Default allow-list (module prefixes / modules):**

- Safe builtins needed for ordinary pickle reconstruction (`dict`, `list`, `tuple`, `set`, `frozenset`, `bytearray`, …) — **not** `exec`, `eval`, `open`, `__import__`, `compile`, `input`, or similar.
- `paramz` / `paramz.*`
- `numpy` / `numpy.*`
- `GPy` / `GPy.*` (primary consumer of this loader)

**Reject** anything else with an `UnpicklingError` (or a thin subclass) that shares the blocked `module.name`.

**Configurable extension:** `paramz.load(..., allow_modules=["mypkg"])` merges extra prefixes into the allow-list so downstream apps with their own `Parameterized` subclasses can load without opting into full pickle.

### API surface

```text
paramz.load(path)                             # restricted (default)
paramz.load(path, allow_modules=["mypkg"])    # restricted + extra prefixes
paramz.load(path, trusted=True)               # stock pickle; documented unsafe
```

- Default path: restricted only.
- `trusted=True`: current behaviour (stock `pickle.load`), with a warning (or docs-only note if warning noise is a concern for libraries). Prefer a one-line `warnings.warn` on first use or every call — decide at implementation; lean toward always warn so misuse is visible.
- Do not invent a second public entry point name unless `trusted` proves awkward for GPy wrapping.

### Limits 

Prefix allow-listing stops classic builtins gadgets (the reported PoC). It does **not** make adversarial files fully safe if an allow-listed class implements a hostile `__reduce__` / `__setstate__`. Docs must still say: only load pickles from sources you trust.

### Out of scope

- Replacing pickle as the durable format (see cip0016 in <https://github.com/SheffieldML/GPc>, Shared JSON/YAML model interchange with GPy and GPmat).
- Auditing every GPy / third-party `__reduce__`.
- Changing `Parameterized.pickle` write path (still writes pickle).

### Alternatives considered

| Approach | Why not first |
| --- | --- |
| Document-only "don't load untrusted files" | Does not close the default footgun; reporters and users expect a code fix. |
| Ban pickle / new format only | Correct long-term; breaks ecosystem immediately. |
| Deny-list of dangerous names only | Easy to miss gadgets; allow-list of modules is the usual pattern. |

## Implementation Plan

1. Add restricted `Unpickler` + allow-list helper; wire `_unpickle` / `load` to use it by default.
2. Add `allow_modules` and `trusted` kwargs on `load`; document them in the docstring.
3. Tests: gadget payload fails on default path; existing `pickle_tests` / round-trips pass; optional `trusted=True` still loads the gadget (proves escape hatch) or is covered by a unit test that mocks `find_class` behaviour.
4. Docs: README / load docstring note on trust; CHANGELOG for patch release.
5. Patch bump (e.g. 0.10.2); credit reporter (Dilanka Kaushal Hewage / r3vpwnx); close #60. Consider CVE filing after the patch is public.

## Backward Compatibility

- **Legitimate paramz/GPy pickles** that only reference allow-listed modules: no change.
- **Pickles that reconstruct via third-party modules** outside the default prefixes: need `allow_modules=[...]` or `trusted=True`.
- **Callers relying on arbitrary code during load**: broken by design; use `trusted=True` only for files they authored.

No change to on-disk pickle bytes written by `m.pickle(...)`.

## Testing Strategy

- Regression: craft a minimal `__reduce__` → `exec` (or `builtins.exec`) payload; assert default `paramz.load` raises and does not perform the side effect.
- Compatibility: existing suite (`paramz/tests/pickle_tests.py` and related) green under restricted load.
- Escape hatch: `trusted=True` accepts the gadget (or a dedicated unit asserting unrestricted path uses stock load).
- Manual / optional: load a small GPy model pickle if available in CI; otherwise document as release smoke check.
