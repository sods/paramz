# CIP-0001: Adopt VibeSafe project governance

## Status

- [x] Proposed - Initial idea documented
- [x] Accepted - Approved, ready to start work
- [x] In Progress - Actively being implemented
- [x] Implemented - Work complete, awaiting verification

## Summary

Install VibeSafe, announce adoption, triage open GitHub issues/PRs into tenets, requirements, CIPs, and backlog tasks, and keep Sphinx/RTD as the user-facing API docs.

## Motivation

paramz has a small set of long-lived issues and intermittent maintenance. VibeSafe gives a local paper trail so design work (pickle, NumPy buffer, observer notify) does not live only in PR descriptions.

## Detailed Description

- Scaffolding (templates, validator, `AGENTS.md`, `.venv-vibesafe`) stays gitignored.
- Project content (tenets, requirements, CIPs, backlog tasks) is committed.
- Discussion #52 records the experiment for the community.
- Open issues/PRs are mapped once into vibesafe; GitHub remains the public tracker.

## Implementation Plan

1. Install VibeSafe + `whats-next`.
2. Enable Discussions; post adoption announcement.
3. Draft tenets from existing design philosophy.
4. Survey open issues/PRs → requirements + CIPs + backlog.
5. Run validator / `whats-next` and adjust.

## Backward Compatibility

No runtime API change.

## Testing Strategy

- `./whats-next` runs.
- `scripts/validate_vibesafe_structure.py` reports no governance drift for new artifacts.
